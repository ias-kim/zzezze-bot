# 실행 계획: 1차 배포 "약속 카드"

- 브랜치: `feat/phase1-chicken`(1·2단계, PR #1 병합됨) → `claude/stoic-brown-623ddx`(방향 전환)
- 설계: [docs/design/six-member.md](../../design/six-member.md)
- 시작: 2026-09-23. 2026-10-17에 치킨 판에서 약속 카드로 방향을 바꿨다([ADR 0006](../../adr/0006-meetup-first-rollout.md)). 파일 이름도 `phase1-chicken.md`에서 바꿨다.

## 목표

2번방에서 "30일에 뭐하세요", "같이 피맥?" 같은 말이 나오면 봇이 `[📅 약속 잡기]`를 제안한다. 누르면 날짜와 참석 응답(갈게/미정/패스)을 모으는 약속 카드가 올라가고, 카드에서 시간 투표도 올릴 수 있다. 쮀쮀이야 밈 자동 반응도 같이 내보낸다. **DB는 쓰지 않는다**(2차에서 붙인다).

## 완료 기준

- [ ] `make check`가 통과한다 (검사 항목은 Makefile `check` 타깃이 원천)
- [ ] `main.go`와 `features/` 밖의 패키지가 discordgo를 import하지 않는다 (`make layers`로 강제, 테스트 파일 포함)
- [ ] 트리거 테스트 데이터(`meetup/testdata/hit.txt`, `miss.txt`)가 실제 2번방 문장으로 채워져 있다. hit은 10줄 이상이고 `~맥` 문장이 3줄 이상 들어 있다
- [ ] 1차 필터가 hit을 하나도 놓치지 않는다 (`make check`, 테이블 테스트)
- [ ] AI 판정(Haiku 5.5) 정확도: hit 90% 이상을 잡고, miss 오탐은 5% 이하다 (`make eval`, API 키 필요, CI 밖) ([ADR 0007](../../adr/0007-ai-trigger-judge.md))
- [ ] AI 호출이 실패하거나 3초를 넘기면 반응하지 않는다 (가짜 판정기로 테스트)
- [ ] AI에 닉네임·유저 ID가 가지 않는다 (요청 본문 테스트)
- [ ] 배포 전에 원정 멤버들에게 AI 판정을 알리고 동의를 받았다
- [ ] 같은 사람이 60초 안에 이어 보낸 메시지는 묶어서 판정한다 ("30일에 저희 / … 함께하실래요" 사례를 테스트)
- [ ] 1번방에서는 약속 제안이 나오지 않고, 자동 반응은 mild 톤으로만 나온다
- [ ] 날짜 해석: 오늘/내일/모레, `N일`(지났으면 다음 달), `N월 N일`, `(다음주) X요일`을 KST 기준으로 해석한다 (월말, 연말, 오늘이 그 요일인 경우를 테스트)
- [ ] 약속 카드: 응답을 바꾸면 이전 응답이 지워지고, 날짜가 없으면 앞으로 7일 중에서 고르는 선택 메뉴가 나온다
- [ ] 시간 투표: 카드 날짜의 18~23시 정각으로 기본 투표(복수 선택)가 올라간다. 날짜가 오늘이면 지난 시각은 빠지고, 모두 지났으면 버튼이 꺼진다. 날짜가 정해지기 전에도 버튼이 꺼진다 (KST 22:30과 23:30 경계를 테스트)
- [ ] 카드는 약속 날짜가 끝나는 KST 자정에, 날짜가 미정이면 마지막 행동부터 48시간 뒤에 닫힌다
- [ ] `[🔕 오늘 그만]`을 누르면 KST 자정까지 약속 제안이 멈춘다
- [ ] SIGTERM을 받으면 열린 카드의 버튼이 꺼지고 재시작 안내가 표시된다
- [ ] 테스트 서버에서 위 흐름을 손으로 한 번 확인했다
- [ ] EC2에 원자적 배포 스크립트로 배포했다
