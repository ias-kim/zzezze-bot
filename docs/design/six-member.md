# 설계: 쮀쮀이야 봇 — "여섯 번째 멤버"

- 상태: 승인됨 (2026-09-23, /office-hours → /plan-eng-review CLEAR)
- 원본 세션 기록: `~/.gstack/projects/zzezze-bot/gwan-main-design-20260923-104757.md` (로컬 전용. 레포 안의 원천은 이 문서)
- 관련 ADR: [0002](../adr/0002-discordgo-v029-poll.md), [0003](../adr/0003-pure-core-shared-session.md), [0004](../adr/0004-chicken-first-rollout.md), [0006](../adr/0006-meetup-first-rollout.md), [0007](../adr/0007-ai-trigger-judge.md)

## 문제

BM 증바람 서버의 두 방은 성격이 다르다.

- **1번방 #채팅방**: 원정 멤버 5명의 초기 메인 방이었는데, 비핵심 인원이 들어오면서 시들해졌다. 봇의 목표는 "살리기"가 아니라 **소음을 더하지 않기**다.
- **2번방 #개꿀이즤**: 원정 멤버 전용 방. 게임 근황과 약속 조율("30일에 뭐하세요", "같이 피맥?")이 실시간으로 오간다. 약속은 대개 며칠 뒤 날짜로 잡히고, 자세한 조율은 DM으로 넘어가기도 한다.

5명이 빠르게 떠드는 방에서는 아무도 명령어를 치지 않는다. 그래서 봇은 **이미 오가는 말에 반응해야** 쓰인다.

## 전제 (합의됨)

1. 단순 투표는 디스코드 기본 투표로 충분하다. 시간 집계도 기본 투표(복수 선택)에 맡긴다.
2. 1번방은 봇으로 되살릴 수 없다. 1번방에서는 소음을 최소화한다.
3. 관리 명령(`/공지`, `/고정`, `/청소`)은 범위에서 뺀다.
4. 관리 웹사이트와 웹 기반 게임 화면은 범위에서 뺀다.
5. 포인트는 SQLite(`modernc.org/sqlite`, 순수 Go)에 저장한다(2차).
6. **현실 돈은 다루지 않는다.** 포인트는 가상이고, 누가 계산할지는 봇이 정하지 않는다.

## 채널별 기능

|---|---|---|---|
| `AutoReply` | ○ (mild) | ○ (full) | 쮀쮀이야 계열 밈 반응. 방별 쿨다운 |

## 구조와 의존 방향

```
main.go ──▶ features/ ──▶ meetup/ yacht/ session/ voice/ config/ interactions/ store/
   │            │
   └─ discordgo ┘   ← discordgo 는 main 과 features/ 만 import 한다
```

| 패키지 | 역할 | discordgo |
|---|---|---|
| `config/` | 채널 → 기능, 톤 | ✕ |
| `interactions/` | custom_id 형식 `기능:동작[:인자]` codec | ✕ |
| `voice/` | 모든 봇 대사(full/mild), 주사위 눈 | ✕ |
| `session/` | 메시지 ID를 키로 판 상태 보관, 타이머, 종료 1회 보장, 유저 역인덱스 | ✕ |
| `meetup/` | 약속 트리거 판정, 메시지 묶기, 날짜 해석, 카드 상태 | ✕ |
| `yacht/` (2차) | 순수 게임 로직 (`Score`, `Duel.Apply`) | ✕ |
| `store/` (2차) | SQLite 원장. 모든 함수가 `*sql.Tx`를 받음 | ✕ |
| `features/` | 디스코드 이벤트 ↔ 순수 로직 변환, 화면 그리기 | ○ |

이 규칙은 `make check` 안에서 `scripts/check-layers.sh`가 검사해 강제한다.

## 공통 규칙

- **시간대**: KST로 고정한다. `time.LoadLocation("Asia/Seoul")`와 `import _ "time/tzdata"`를 쓴다.
- **상호작용 응답**: 버튼 입력에는 3초 안에 `InteractionResponseUpdateMessage`로 응답한다. 타이머로 메시지를 바꿀 때는 `ChannelMessageEdit`를 쓴다(상호작용 토큰은 15분 뒤 만료되기 때문).
- **만료 버튼**: Registry에 판이 없으면 (1) 버튼을 모두 끄고, (2) Ephemeral 후속 메시지로 `voice.SessionExpired`를 보낸다.
- **기능이 꺼진 채널**: 슬래시 커맨드가 오면 Ephemeral `voice.WrongChannel`로 거절한다.
- **말투**: 봇 대사는 전부 `voice.Say(키, 톤, picker, 치환...)`로만 가져온다. 로직 코드에 한국어 문자열을 직접 쓰지 않는다.
- **종료 순서**: SIGTERM → `Registry.CloseAll()`(5초 제한, 버튼 끄기와 `voice.SessionRestart` 표시) → `db.Close()` → `dg.Close()`.

## session.Registry

- 메시지 ID를 키로 판 상태를 보관하고, 판마다 락을 따로 둔다(`Session.Lock`). 락 순서는 판 락 → 레지스트리 락이다. 레지스트리는 자기 락을 쥔 채로 판 락을 잡거나 `OnExpire`를 부르지 않는다.
- `Add(Spec)`로 판을 등록하고 방치 타이머를 건다. `Spec.Users`에 넣은 유저만 역인덱스에 묶인다.
  - 1:1 대결(2차)은 묶는다. 한 유저는 수락 대기 중인 판까지 포함해 **동시에 판 1개**만 가질 수 있다(`ErrBusy`).
  - 약속 카드는 묶지 않는다. 한 사람이 여러 약속에 동시에 응답할 수 있다.
- `Touch(msgID, d)`는 타이머를 재설정한다. 방치 시간은 **마지막 행동부터** 센다. 멈추기 직전에 울린 옛 타이머는 세대 번호로 무시한다.
- `Finish(msgID)`는 처음 호출됐을 때만 true를 돌려주고, 판과 유저 역인덱스를 함께 지운다. 그래서 타이머 만료와 클릭이 동시에 들어와도 한 번만 끝난다. 만료로 끝나면 `Spec.OnExpire`가 한 번 불린다.
- `CloseAll()`은 종료할 때 모든 타이머를 멈추고 남은 판 목록을 돌려준다. 그 뒤의 `Add`는 `ErrClosed`를 받는다.

## 2번방 약속 트리거 (`meetup/` + `features/nudge.go`)

### 트리거 ([ADR 0007](../adr/0007-ai-trigger-judge.md))

판정은 두 단계로 한다. 둘 다 통과하면 `[📅 약속 잡기] [🔕 오늘 그만]`을 띄운다.

1. **1차 필터** (`meetup/`, 순수 코드): 아래 신호 중 **하나라도** 있는 판정 단위만 통과시킨다. "ㅋㅋ", "롤하면 됨" 같은 대부분의 잡담은 여기서 걸러져 AI를 부르지 않는다.

   | 신호 | 예 | 주의 |
   |---|---|---|
   | `~맥` | 피맥, 치맥, 소맥 | `맥북`, `맥날`, `맥도날드`, `맥락`은 뺀다 |
   | 날짜/시간 말 | 오늘, 내일, 모레, `N일`, `N월 N일`, `X요일`, 주말, `몇\s*시`, `N시`, `언제` | |
   | 제안 말 | 같이, 함께, 뭐하세요/뭐함, 볼래, 만날, 시간 돼 | `ㄱ`, `ㄱㄱ`, `?`는 신호로 치지 않는다 |

2. **AI 판정** (모델: Claude Haiku 5.5): 통과한 판정 단위를 보내고 `{제안 여부, 날짜 표현 원문}`을 받는다. 예: `{"proposal": true, "date_text": "30일"}`
   - 판정 인터페이스는 `meetup/`에 두고, API를 부르는 구현체는 `features/`에 둔다. 테스트에서는 가짜 판정기를 쓴다.
   - 메시지 본문만 보낸다. 닉네임과 유저 ID는 보내지 않고, 멘션은 `@멤버`로 바꾼다.
   - 실패하거나 3초 안에 답이 없으면 반응하지 않는다.

- **판정 단위**: 같은 사람이 60초 안에 이어 보낸 메시지는 하나로 묶어서 판정한다. 실제로 "30일에 저희" / "… 함께하실래요"처럼 나눠 보낸다.
- 봇 메시지와 명령어 메시지에는 반응하지 않는다.

### 약속 카드

```
📅 약속 — 10/18 (일)          ← 날짜가 없으면 "날짜 미정" + 선택 메뉴
🙋 갈게: A, B
🤔 미정: C
🙅 패스: D
[🙋 갈게] [🤔 미정] [🙅 패스] [⏰ 시간 투표]
```

- **날짜**: AI가 돌려준 날짜 표현 원문을 `meetup/`의 순수 함수가 KST 기준 날짜로 바꾼다. AI에게 날짜 계산을 맡기지 않는다.
  - 오늘/내일/모레
  - `N일`: 이번 달 N일. 이미 지났으면 다음 달 N일
  - `N월 N일`: 이미 지났으면 내년
  - `X요일`: 오늘을 포함해 가장 가까운 X요일. `다음주 X요일`은 다음 주 월~일 중 X요일
  - 날짜가 여러 개면 첫 번째를 쓴다. 날짜가 없으면 카드에 앞으로 7일 중에서 고르는 **선택 메뉴**를 띄운다. 누구나 고를 수 있고 나중에 바꿀 수 있다.
- **응답**: 누구나 누를 수 있다. 한 사람은 응답 하나만 가진다(다른 걸 누르면 바뀐다). 누를 때마다 카드를 다시 그린다.
- **시간 투표**: `[⏰ 시간 투표]`를 누르면 봇이 디스코드 **기본 투표**를 복수 선택으로 올린다. 선택지는 카드 날짜의 18~23시 정각이다. 날짜가 오늘이면 지난 시각은 뺀다. 남은 시각이 없거나 날짜가 정해지지 않았으면 버튼을 끈다. 투표는 3시간 뒤 마감한다.
- **장소**: 1차에서는 다루지 않는다. 실제 대화에서 장소는 후보 이름이 아니라 조건("근처", "지하철 있는 곳", "막차")으로 나와서 투표로 만들기 어렵다.
- **수명**: 약속 날짜가 끝나는 KST 자정에 닫는다. 날짜가 미정이면 마지막 행동부터 48시간 뒤에 닫는다. 닫히면 버튼을 끈다.
- 포인트는 움직이지 않는다.

### 그 밖의 대화 반응

- **밈** (`features/autoreply.go`, 두 방 모두): "쮀쮀" 계열에만 반응한다. "줘줘", "졸졸"은 평범한 말에 오작동하므로 제외한다. 패턴이 단순해서 테스트 안의 표로 충분하다.
- **소음 제어**: 트리거별·채널별 쿨다운은 30분이다. `[🔕 오늘 그만]`을 누르면 KST 자정까지 해당 트리거를 멈춘다.
- **트리거 테스트 데이터**: 실제 2번방 문장으로 `meetup/testdata/hit.txt`, `miss.txt`를 만든다. 1차 필터는 `make check`에서 hit을 하나도 놓치지 않는지 테이블 테스트로 고정한다. AI 판정의 정확도는 `make eval`(API 키 필요, CI 밖)로 잰다. 한 줄이 판정 단위 하나이고, 묶인 메시지는 ` / `로 잇는다. 사람 이름은 `○○`로 바꿔 넣는다.

## 야추 (2차)

### 족보 (하우스 룰, 51 Worldwide Games 기준)

| 족보 | 조건 | 점수 |
|---|---|---|
| 1~6 | 없음 | 해당 눈의 합 |
| Choice | 없음 | 주사위 5개의 합 |
| Four of a Kind | 같은 눈 4개 이상 | 5개의 합 |
| Full House | 정확히 3+2 (야추는 인정하지 않음) | 5개의 합 |
| Small Straight | 연속 4개 | 15 |
| Large Straight | 연속 5개 | 30 |
| Yacht | 5개 모두 같음 | 50 |

조건을 만족하지 못하면 0점이다. 상단 보너스(63점 이상이면 +35)는 정식 12라운드 모드(3차)에서만 쓴다.

### 빠른 1:1 대결 (`/야추 상대 판돈`)

```
 Challenged ──accept(상대만)──▶ TurnA ──confirm──▶ TurnB ──confirm──▶ Settled
     │  └─decline / 60s──▶ Cancelled   │ roll≤3, hold    │ roll≤3, hold
     └─(자기/봇 도전 → 생성 거부)       └─3분 방치──▶ Forfeit(A 패) └─3분 방치──▶ Forfeit(B 패)
 어느 상태든 ──CloseAll(종료)──▶ Cancelled (포인트 이동 없음)
```

- 게임 규칙은 순수 함수 `yacht.Duel.Apply(Event{User, Action, Now})`가 모두 결정한다. `features/yacht.go`는 입력을 변환하고, 화면을 그리고, store를 호출하는 일만 한다.
- 수락할 때 확인하는 것: 판돈이 1 이상인지, 두 사람 모두 잔액이 판돈 이상인지, 두 사람 모두 진행 중인 판이 없는지.
- 수락하는 순간 12개 족보 중 **오늘의 족보** 하나를 무작위로 정한다. 두 사람 모두 이 족보로 겨룬다.
- 턴이 시작되면 첫 굴림은 자동이고, 그 뒤로 최대 2번 더 굴릴 수 있다(총 3회). `[확정]`은 언제든 누를 수 있다.
- 점수가 높은 쪽이 판돈을 가져간다. 둘 다 0점이면 주사위 합계로 가리고, 합계까지 같을 때만 무승부(포인트 이동 없음)다.
- 3분 동안 아무것도 안 하면 방치한 쪽이 기권패한다.

### 화면

서버 커스텀 주사위 이모지 6개를 쓴다(없으면 1️⃣~6️⃣로 대체). 홀드 버튼 5개가 곧 주사위이고, 홀드한 주사위는 Primary(파란색)로 표시한다.

```
🎲 야추 빠른 대결 — 판돈 50
오늘의 족보: 풀하우스
니얼굴디크  ⚀ ⚂ ⚂ ⚂ ⚀  → 11점 ✅
상대방      (대기 중)
── 니얼굴디크의 턴 · 굴림 2/3 ──
[⚀] [⚂] [⚂] [⚂] [⚀]      ← 파란 = 홀드
[🎲 굴리기] [✅ 확정]
```

### 포인트 원장 (`store/`)

- 테이블은 두 개다. `ledger(guild_id, user_id, delta, reason, match_id, created_at)`는 append-only로만 쓰고, `matches(guild_id, kind, channel_id, result_json, created_at)`에 판 결과를 남긴다. 스키마 원천은 2차에 `store/schema.sql`로 만든다.
- 잔액은 `SUM(delta)`로 계산한다. welcome 포인트 1000은 `(guild_id, user_id) WHERE reason='welcome'` UNIQUE 부분 인덱스로 한 번만 지급한다.
- **정산 순서**: DB 커밋 → 메시지 수정. 커밋이 실패하면 `voice` 정산 실패 대사를 띄우고 결과 JSON을 로그에 남긴다.
- 정산 트랜잭션 안에서 진 쪽의 잔액을 다시 확인한다. 판돈보다 적으면 가진 만큼만 옮긴다.
- DSN은 `file:data/zzezze.db?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)`이고, `SetMaxOpenConns(1)`로 연결을 하나만 쓴다.
- 테스트는 `t.TempDir()`에 만든 파일 DB로 한다.

## 배포

- `GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build`로 빌드하고, **EC2 t4g.nano**(서울)에서 systemd로 띄운다. Go 봇은 메모리를 수십 MB만 써서 nano(512MB)로 충분하다. 비용은 `docs/harness/profile.md` 참고.
- 배포는 원자적으로 한다. `zzezze-bot.new`로 업로드한 뒤 `mv`로 바꿔치기하고 `systemctl restart`한다.
- (2차) DB는 매일 `sqlite3 .backup`으로 백업하고, 백업본은 **EC2 밖**(로컬 Mac 또는 S3)에 보관한다.

## 범위 밖

## 열린 질문

- 포인트를 다 잃은 사람이 다시 참여할 방법(일일 보너스 등). 2차 배포 첫 주 결과를 보고 정한다.
- 1번방 자동 반응 쿨다운의 적정값.

## 성공 기준

- 1차 배포 후 2주 안에 약속 카드에 3명 이상이 응답한 약속이 한 번 이상 생긴다.
- 2주 동안 `[🔕 오늘 그만]`이 눌린 날이 3일 이하다.
- 2차 배포 후 첫 주말에 최소 2쌍이 `/야추` 대결을 한다. 봇을 재시작해도 잔액이 그대로 유지된다.
